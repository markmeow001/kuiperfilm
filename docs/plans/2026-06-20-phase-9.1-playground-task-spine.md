## 拍板決策（user 2026-06-20，A+A）

- **projectId**：用合成哨兵 `'playground'`。`Task.projectId` 是 NOT NULL 但
  **無 FK 指向 Project**（已查證 schema：只有 `user @relation`），且
  `billing/reporting.ts:VIRTUAL_PROJECT_IDS` 早已白名單 `'playground'`
  （skips UsageCost，仍寫 BalanceTransaction）。→ **零 schema 改動、零 migration**。
- **PlaygroundRun 表**：Task 變唯一真相。新任務只寫 Task；既有 PlaygroundRun
  row 凍結成 9.1 前唯讀歷史（**不雙寫、不 migrate、不刪表**）。前端歷史改讀 Task。

被否決：projectId nullable（要 migration）/ 每用戶虛擬專案（要 backfill）/
PlaygroundRun 當投影（踩 `no-multiple-sources-of-truth` guard）。

## 已驗證契約（讀過真實 code）

- `submitTask`（`src/lib/task/submitter.ts:94`）一手包辦：rate-limit → skill
  constraint → `buildDefaultTaskBillingInfo` → `createTask` →（`isAiTaskType`）
  `createRun`+`attachTaskToRun`+把 runId 蓋回 payload → `prepareTaskBilling`
  （凍結，餘額不足丟 `InsufficientBalanceError`→402）→ `publishTaskEvent(CREATED)`
  → `addTaskJob`（enqueue 失敗會 rollback billing + markTaskFailed）。回
  `{taskId, runId, status, deduped}`。
- `isAiTaskType`（`run-runtime/workflow.ts`）= 全部 TASK_TYPE；
  `workflowTypeFromTaskType` = identity。→ **註冊進 TASK_TYPE 即自動建 run，零 workflow 接線**。
- `withTaskLifecycle`（`src/lib/workers/shared.ts:218`）：mark processing → 跑
  handler 收 `result` + textUsage →（billable）`settleTaskBilling`（capture）+
  `updateTaskBillingInfo` → mark completed(result) + COMPLETED event；錯誤
  → `rollbackTaskBilling`。→ **handler 只要回 `{resultUrls:[cosKey]}`，計費/狀態/事件全自動**。
- 計費政策（`src/lib/billing/task-policy.ts`）：`buildImageTaskInfo` 讀
  `payload.imageModel|modelId|model` + `resolution`；`buildVideoTaskInfo` 讀
  `payload.videoModel|modelId|model` + `resolution` + `duration`。→ payload 帶
  `modelId`（resolveModelSelection 解出的 bare id）+ `resolution` + `duration` 即可重用。
- tasktype-coverage guard（`scripts/guards/test-tasktype-coverage-guard.mjs`）：每個
  TASK_TYPE key 必須在 `tests/contracts/task-type-catalog.ts` 有 `[TASK_TYPE.X]` owner。

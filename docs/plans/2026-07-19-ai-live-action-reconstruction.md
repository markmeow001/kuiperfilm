# Kuiper AI 實拍角色重製與動態換景計畫

> 日期：2026-07-19  
> 狀態：產品與技術規劃草案  
> 適用範圍：Live Composite、Canvas、Playground、素材庫、導演台  
> 核心目標：保留演員的表演、口型與鏡頭節奏，只重新生成指定的人物外觀、服裝、妝容與場景。

## 1. 決策摘要

Kuiper 不應再把目前的 Live Composite 定位成單純的「人物去背／遮罩工具」，而應升級成「AI 實拍重製工作區」。

產品採用兩條明確管線：

1. **綠幕專業模式**：以 chroma key 取得可靠前景，再用生成式影片模型完成特效妝、服裝、角色與場景重製。
2. **一般實景模式**：以影片物件分割、跨影格追蹤及人工關鍵影格修正處理既有素材。

遮罩是生成與合成的控制資料，不是最終效果。正式換景不得把單張背景圖直接當作完整影片背景；單張圖只能作為構圖預覽、背景概念圖或影片生成參考。

建議優先順序：

`綠幕 Keying → 工作流改版 → 動態背景 → 特效妝 → AI 換裝 → 完整角色替換 → 自動品質檢查`

## 2. 現有基線

目前平台已具備：

- 本機 MediaPipe 人物分割。
- 人物遮罩關鍵影格與手動畫筆修正。
- 單張背景圖片／純色背景合成。
- AI 背景概念圖生成。
- 前景遮擋遮罩。
- 透明圖片／影片角色圖層。
- 基礎人物中心追蹤、位置校正與動作參考。
- Canvas 預覽、單幀輸出、影片錄製、專案儲存及素材庫串接。

目前限制：

- 自拍分割模型不適合複雜實拍、多人、婚紗、頭髮、半透明材質及大幅動作。
- 分析影格之間主要依遮罩形變插值，不是真正的影片物件追蹤。
- AI 背景是一張圖片，未匹配攝影機運動與環境動態。
- 虛擬角色是透明素材圖層，不是生成式演員替換。
- 尚未提供臉部區域妝容、影片虛擬試衣或身份鎖定。
- 尚未提供完整的閃爍、破臉、邊緣外漏與身份漂移檢查。

## 3. 產品目標與品質定義

### 3.1 應保留的內容

- 演員動作、走位、表情與演出節奏。
- 原始口型、台詞時間與聲音。
- 攝影機運動、鏡頭長度與剪接點。
- 未被使用者指定修改的畫面區域。
- 角色身份；只有在「完整角色替換」模式才允許改變身份。

### 3.2 可重新生成的內容

- 局部妝容、傷妝、老化與奇幻造型。
- 服裝、盔甲、材質與配件。
- 頭髮、身形或完整角色外觀。
- 背景、天空、建築、環境物件及特效。
- 接觸陰影、反射、環境光、景深與動態模糊。

### 3.3 不承諾的內容

- 任意長度、任意運鏡與任意遮擋都能一次生成成功。
- 在重新生成妝容、服裝或身份時仍逐像素保留原人物。
- 第一版直接原生生成 4K 長影片。
- 不經人工檢查即可交付的多人快速動作鏡頭。

第一版的可交付範圍應限制為：單一主要演員、5–15 秒、1080p 預覽、固定或緩慢運鏡。4K 應採通過驗收後的升頻輸出，而不是初期生成基線。

## 4. 核心工作流

### 4.1 統一入口

Live Composite 更名為「AI 實拍重製」，進入後先選擇素材類型：

- **綠幕／藍幕素材**
- **一般實景素材**

系統可以提出偵測建議，但不得在未告知使用者的情況下自動切換模式。

### 4.2 綠幕專業模式

`上傳影片 → 選取幕布顏色 → 去背／去溢色 → 修正人物邊緣 → 鎖定表演 → 選擇人物改造 → 建立背景參考 → 生成背景影片 → 合成與品質檢查 → 輸出`

必要控制：

- 綠幕／藍幕色彩取樣。
- 色彩距離與去背容差。
- 亮度範圍與陰影保留。
- 綠色／藍色溢色消除。
- 邊緣收縮、羽化、去污染。
- 頭髮、薄紗及動態模糊的半透明 alpha。
- Garbage matte 與 holdout matte。
- 時序平滑與問題影格修正。
- 原片、alpha、去背、生成、合成五種檢視。

### 4.3 一般實景模式

`上傳影片 → 點選演員 → 跨影格追蹤 → 檢查問題區段 → 關鍵影格修正 → 鎖定表演 → 人物改造／換景 → 品質檢查 → 輸出`

必要能力：

- 點、框與遮罩提示選取演員。
- 向前／向後影片分割傳播。
- 多物件 mask ID，不把不同演員合併為單一人物遮罩。
- 遮擋消失後重新辨識。
- 頭髮、臉部、皮膚、上衣、下身、手、鞋及道具語意分層。
- 使用者修正一個影格後，明確選擇傳播範圍。
- 修正失敗時顯式顯示，不得靜默沿用錯誤遮罩。

## 5. 人物改造模組

### 5.1 特效妝

使用者流程：

1. 選擇演員。
2. 上傳妝容參考圖或輸入描述。
3. 選擇修改區域：全臉、皮膚、眼周、嘴唇、傷口、疤痕或自訂遮罩。
4. 鎖定眼球、牙齒、鼻孔、髮際線及口型。
5. 先生成單格與 2–3 秒預覽。
6. 確認後生成整個鏡頭。

技術條件：

- Face mesh／landmarks。
- 臉部語意分割。
- 身份參考與身份相似度檢查。
- 區域式生成，不重新生成整張臉。
- 表情、口型及閉眼狀態的跨幀一致性。

### 5.2 AI 換裝

使用者流程：

1. 上傳服裝正面、背面與細節參考。
2. 選擇上衣、下身、全身、鞋或配件。
3. 設定材質、顏色與服裝年代。
4. 檢查手臂、頭髮與道具遮擋。
5. 生成短預覽後再生成全鏡頭。

技術條件：

- 人體姿勢、身體語意區域與深度資訊。
- 服裝參考圖條件化。
- 手部、頭髮、道具與衣服的前後遮擋。
- 布料形變、摺痕及時間一致性。
- 僅重繪衣服及必要的鄰接像素。

### 5.3 完整角色替換

使用者流程：

1. 上傳經授權的角色參考圖／影片。
2. 選擇保留原臉或替換身份。
3. 指定髮型、體型、服裝與配件鎖定項目。
4. 以原演員影片作為動作、表情及口型驅動。
5. 生成低解析預覽。
6. 對問題區段重新生成，不重算整個鏡頭。

此模組屬於 performance transfer／video-to-video，不應與透明角色圖層功能混為一談。現有透明角色仍保留為快速合成工具。

## 6. 動態背景管線

### 6.1 名詞修正

- **背景概念圖**：用於構圖、藝術方向和生成條件。
- **背景影片**：正式合成使用的時間素材。
- **靜態背景預覽**：只供固定鏡頭快速預覽，不視為一般正式輸出。

UI 中現有「AI 生成背景」應改名為「建立背景概念圖」。

### 6.2 背景製作流程

`背景描述／參考圖 → 背景概念圖 → 使用者確認 → 原鏡頭分析 → 選擇背景運動模式 → 背景影片生成 → 光影匹配 → 合成`

提供三種背景運動模式：

1. **固定攝影機＋環境微動**：樹葉、煙霧、窗外、燈光及人流等背景元素自然運動。
2. **2.5D 深度視差**：將背景分成前、中、遠景，依原鏡頭平移、推拉及旋轉產生視差。
3. **完整生成式背景影片**：以概念圖為首幀／視覺參考，生成具有攝影機與環境運動的背景影片。

正式合成需要匹配：

- 攝影機平移、旋轉、推拉與手持抖動。
- 焦距、透視與消失點。
- 地面接觸位置與人物比例。
- 景深、散景、快門及動態模糊。
- 光線方向、色溫、曝光與環境反射。
- 原影片顆粒、壓縮及銳利度。

## 7. UI／UX 資訊架構

左側採八步引導，不直接向一般使用者暴露所有技術控制：

1. **素材**：上傳影片、選擇綠幕或實景。
2. **人物**：點選演員、多人管理。
3. **分離**：去背、追蹤與問題影格。
4. **造型**：妝容、服裝或完整角色替換。
5. **場景**：建立背景概念圖及背景影片。
6. **預覽**：2–3 秒、低解析、多版本比較。
7. **檢查**：自動品質警告與局部重算。
8. **輸出**：解析度、音訊、升頻、素材庫及 Canvas。

畫面中央維持時間軸與播放器，右側提供當前步驟的進階參數。預設只顯示必要控制；Garbage matte、追蹤校正、深度與光影等放入「進階修正」。

每個生成步驟必須顯示：

- 會修改的區域。
- 會保留的內容。
- 預估時間與費用。
- 模型與版本。
- 原始結果、目前版本及替代版本。
- 失敗原因及可重新生成的範圍。

## 8. 系統架構

### 8.1 非破壞性資料模型

每個實拍重製專案應保存：

- 原始影片 asset ID。
- 鏡頭區段與時間範圍。
- 人物／服裝／臉部／背景遮罩版本。
- 綠幕 keying 參數。
- 追蹤提示與人工修正關鍵影格。
- 人物、妝容、服裝及背景參考素材。
- 姿勢、臉部、深度、鏡頭與光影分析結果。
- 每次生成任務、模型、提示詞、seed、費用及輸出版本。
- 合成參數與最終輸出 asset ID。

任何生成結果都建立新版本，不覆蓋原片、遮罩或已核准成果。

### 8.2 任務管線

建議任務階段：

1. `analyze-shot`
2. `key-green-screen` 或 `track-subject`
3. `analyze-performance`
4. `generate-makeup`／`generate-wardrobe`／`generate-character`
5. `generate-background-reference`
6. `generate-background-video`
7. `composite-shot`
8. `quality-check`
9. `upscale-export`

正式實作時應優先重用平台既有 Playground task spine、任務狀態、計價、資產與 worker；是否新增 task type 需逐項確認契約，不能以 UI 假進度取代後端任務。

### 8.3 模型與運算原則

- 瀏覽器保留即時預覽、簡易筆刷和低成本分析。
- 綠幕 keying 可先採瀏覽器／GPU shader 預覽，正式高品質輸出由後端 worker 執行。
- 影片物件追蹤、生成式換裝、角色替換與背景影片由 GPU worker 或既有供應商任務處理。
- 模型不可用時必須顯式失敗，不自動降級到另一模型。
- 新增外部 SaaS／API 前需另行確認供應商、費用、授權、資料保存與地區可用性。

## 9. 分階段執行計畫

### Phase 0：現有能力重新命名與邊界修正

目標：停止讓使用者誤以為單張背景合成等同正式 AI 換景。

- Live Composite 改為「AI 實拍重製」。
- 「AI 生成背景」改為「背景概念圖」。
- 靜態圖僅標示為即時構圖預覽。
- 「虛擬角色」明確標示為透明素材合成，不宣稱角色生成。
- 顯示目前引擎限制。

驗收：使用者能在第一次進入時正確理解目前功能和最終生成能力的差異。

### Phase 1：綠幕 Keying 1.0

- 綠／藍幕顏色取樣。
- 容差、邊緣、羽化、溢色消除。
- Garbage matte／holdout matte。
- 全片預覽與遮罩輸出。
- keying 參數保存及還原。
- 針對髮絲、手指、武器及快速動作建立測試素材。

驗收：標準均勻綠幕素材不需逐幀手修；髮絲和武器邊緣沒有明顯綠邊，alpha 在整段播放中不閃爍。

### Phase 2：工作流與動態背景 MVP

- 綠幕／一般實景雙入口。
- 背景概念圖確認流程。
- 固定攝影機環境微動背景影片。
- 背景影片上傳與合成。
- 原始音訊保留。
- 2–3 秒背景預覽及費用顯示。

驗收：可將一段綠幕人物影片與動態 AI 背景合成並輸出，不再使用單張背景充當正式動態場景。

### Phase 3：一般實景人物追蹤 2.0

- 導入真正的影片物件分割／追蹤管線。
- 點選演員、向前／向後傳播。
- 多人物 mask ID。
- 問題範圍偵測與人工修正傳播。
- 頭髮、服裝、手及道具分層。

驗收：教堂、街道、家具等背景不再被大範圍誤納入人物；婚紗、手指及遮擋區段能由有限關鍵影格修正。

### Phase 4：特效妝 MVP

- 臉部 mesh 與區域選取。
- 妝容參考圖／描述。
- 身份、眼睛、牙齒及口型鎖定。
- 單格與短片預覽。
- 問題區段局部重算。

驗收：5–10 秒近景中，妝效隨臉部運動，身份與口型穩定，未選區域不被重新生成。

### Phase 5：AI 換裝 MVP

- 服裝多視角參考。
- 上衣／下身／全身區域選擇。
- 姿勢與遮擋條件。
- 時間一致性與服裝細節鎖定。
- 低解析預覽及正式生成。

驗收：5–10 秒單人中景中，服裝能隨身體運動，手部與道具遮擋關係合理，不出現大面積跨幀變色或版型漂移。

### Phase 6：完整角色替換

- 經授權的角色參考素材。
- 保留原臉／替換身份兩種模式。
- 動作、表情、口型及鏡頭條件。
- 角色一致性與局部重算。
- 與背景影片及 VFX 合成。

驗收：短鏡頭能保留原始表演節奏，角色身份、服裝與配件在整段保持一致；失敗區段可單獨重算。

### Phase 7：品質檢查與正式輸出

- 遮罩外漏、綠邊、alpha 閃爍。
- 臉部身份漂移、五官變形、口型錯誤。
- 衣服變色、手部穿模、道具消失。
- 背景跳動、透視不一致、接地陰影缺失。
- 問題影格時間碼與一鍵跳轉。
- 通過 1080p 後再升頻至 4K。

驗收：每次正式輸出附帶品質報告；重大錯誤會阻止標記為「可交付」，但不刪除或覆蓋生成結果。

## 10. 拍攝端建議

綠幕模式應在平台內提供拍攝檢查表：

- 幕布均勻、沒有皺褶與熱點。
- 演員與幕布保持足夠距離，降低綠色反射。
- 不穿與幕布同色的衣服或道具。
- 快速動作採較清楚的快門，再於合成後補動態模糊。
- 有接觸的武器、椅子與桌面盡量提供替代道具。
- 拍攝色卡、灰球／反光球、鏡頭資料及燈光參考。
- 需要攝影機移動時提供 tracking markers，並拍攝乾淨參考。
- 每個生成鏡頭先控制在 5–15 秒。

## 11. 測試與驗收策略

建立固定測試素材矩陣：

- 固定鏡頭／手持／平移／推拉。
- 短髮／長髮／飛散頭髮。
- 黑衣／白衣／婚紗／半透明材質。
- 空手／持武器／坐椅子／接觸桌面。
- 單人／兩人交錯／短暫離開畫面。
- 正面／側面／轉身／手遮臉／快速動作。

每一階段至少驗證：

- 單元測試：遮罩、時間軸、參數與序列化。
- 契約測試：任務 payload、狀態、計價及輸出資產。
- 整合測試：上傳、分析、生成、保存、刷新後還原及輸出。
- 視覺回歸：固定時間碼的 alpha、人物、背景及合成結果。
- 正式環境 smoke test：不觸發未授權付費生成；付費 E2E 需另行確認。

## 12. 風險與決策門

### 主要風險

- 生成模型對長鏡頭、快速動作和多人遮擋不穩定。
- 原生 4K 成本高且未必比 1080p 生成後升頻更可靠。
- 服裝與妝容參考的授權及演員身份使用需要記錄。
- 不同供應商對 mask、reference video、角色一致性與時間長度的契約不同。
- 若沒有版本化及局部重算，失敗成本會快速增加。

### 實作前需確認

1. 第一版是否只支援綠幕單人短鏡頭。
2. 生成式影片是否先重用平台既有 Kling 能力。
3. 一般實景追蹤採自架 GPU worker 或外部服務。
4. 特效妝與換裝是否允許新增專用模型／供應商。
5. 1080p 預覽、正式生成及 4K 升頻的價格與額度。
6. 演員／角色身份授權紀錄與專案權限要求。

## 13. 建議下一步

先執行 Phase 0 與 Phase 1，不同時開發妝容、換裝與完整角色替換。完成綠幕 Keying 及動態背景 MVP 後，用同一批標準測試素材確認平台已能穩定保留表演並替換場景，再進入生成式人物改造。

第一個可展示里程碑應為：

> 上傳 5–10 秒綠幕演員影片，完成自動去綠、溢色修正，建立一張背景概念圖，再生成匹配長度的背景影片，保留原始表演與音訊，輸出可播放的 1080p 合成影片。

此里程碑完成後，再依序加入特效妝、AI 換裝與完整角色替換。

# LocalMiniDrama — 對標分析

> 對標日期:2026-04-28
> 對標目標:`https://github.com/xuanyustudio/LocalMiniDrama`
> 性質:**個人開發者開源**(MIT License)

## 1. 一句話定位

**「下載即用、完全開源、數據不出本機」**——本地優先 AI 短劇 / 漫劇生成工具,Electron 桌面應用,接你自己的 AI API。

## 2. 技術棧

| 層 | 技術 |
|---|---|
| Frontend | Vue 3 + Vite + Element Plus + Pinia + Axios |
| Backend | Node.js + Express + **SQLite** (better-sqlite3) |
| Desktop | Electron 28 + electron-builder |
| 語言 | **純 JavaScript**(no TypeScript) |

**注意**:純 JS 而非 TypeScript,SQLite 而非 MySQL/Postgres——明確的「個人開發者本地工具」定位。

## 3. 核心 8-Step Pipeline

| Step | 功能 | 說明 |
|---|---|---|
| 1 | 故事生成 | 輸入梗概 + 風格,AI 自動生成多集劇本 |
| 2 | 劇本編輯 | 分集管理,劇本文本可自由編輯 |
| 3 | 角色生成 | AI 提取角色列表,逐個生成角色形象圖 |
| 4 | 場景生成 | 從劇本自動提取場景,生成場景背景圖 |
| 5 | **道具生成** | 從劇本提取/手動添加道具,生成道具圖 |
| 6 | 分鏡生成 | 按集自動生成分鏡腳本(含景別/運鏡/台詞) |
| 7 | 圖片/視頻生成 | 逐鏡生成靜幀圖與視頻片段 |
| 8 | 合成視頻 | 所有分鏡視頻自動合成為完整劇集 |

**特色**:Step 5「道具」獨立成一個 stage,跟「角色」「場景」並列。

## 4. 一鍵流水線特色

> 「**補全並生成:智能跳過已有內容,只補全缺失部分**」
> 「**失敗自動重試:每步最多重試 3 次,應對 429 限流等錯誤,不中斷流程**」
> 「**實時進度展示:執行過程中展示當前步驟與完整錯誤日誌**」

這是非常實用的工程細節:
- 不從零跑,可以從上次斷點繼續
- 自動 retry 應對 rate limit
- 步驟級錯誤日誌

## 5. 重要差異化(KuiperAI 應該關注)

### 5.1 三類資產(角色 + 場景 + 道具)⭐

LocalMiniDrama 與 LumenX 都把「**道具(props)**」作為 first-class asset,跟角色、場景並列。PolyFilm 把道具歸類在角色庫裡。

```
角色 Character ── 全身像、三視圖、頭像
場景 Location ── 背景、室內 / 室外
道具 Prop ── 物件、武器、特殊物品
```

### 5.2 解說旁白(narration)與對白(dialogue)分離 ⭐⭐

> 「**分鏡解說旁白(narration)**:分鏡生成可選『生成分鏡時生成解說旁白』,AI 為每鏡輸出獨立 narration 字段(**與角色對白 dialogue 分離**),便於後期 TTS 與成片旁軌」
> 「**導出解說 SRT**:按分鏡順序與單鏡時長累計時間軸,一鍵導出字幕文件」

這個分離對 TTS / 字幕製作體驗很關鍵:
- `narration`(旁白)— 解說者聲音、做為旁軌
- `dialogue`(對白)— 角色聲音、可分配不同 voice
- 各自可獨立 TTS、合成、導出 SRT

### 5.3 視頻歷史記錄 + 主視頻選擇 ⭐

> 「**視頻歷史記錄與主視頻選擇**:視頻重新生成後自動保留歷史版本,縮略圖條帶一覽,點擊切換主視頻;合成視頻時自動使用當前選定版本」

對應 LumenX 的「multi-batch 抽卡」,但 LocalMiniDrama 是「**保留所有歷史版本**」,合成時用當前選定版本。版本管理思維更完整。

### 5.4 「全能模式」分鏡編輯

> 「**經典分鏡 / 全能模式**:分鏡視圖可一鍵切換。經典模式中間為分鏡參考圖;**全能模式中間為片段描述(獨立存庫,與參考圖並存)**,適合 volcengine_omni(火山 Seedance 2.0 多圖) 或 kling_omni(可靈 Omni) 等全能生視頻鏈路」
> 「**@圖片N 引用語法**:片段描述中可用 `@圖片1`、`@圖片2`... 對應參考圖順序」

這是針對「多圖參考」video model 的 prompt 結構創新:
- 經典模式:單一 prompt + 單一 reference
- 全能模式:**自由文字 + 用 `@圖片N` 排列引用順序**(場景 → 角色 → 物品 → 主圖)

### 5.5 連貫幀模式

> 「視頻幀連貫性(連貫幀模式)」(v1.2.2)

跨分鏡的幀連貫性處理(細節未完全寫,但概念明確:相鄰分鏡的最後幀 ↔ 下一鏡首幀)。

### 5.6 四宮格序列圖模式

> 「四宮格序列圖模式(後端拆分):開關開啟後後端**自動拼裝四宮格提示詞**並用 sharp **拆分為 4 張獨立子圖**,主圖選擇持久化」

讓 image model 一次生四連格(類似漫畫四格),後端再拆成 4 張個別圖。對連續性有幫助。

### 5.7 工程一鍵 ZIP 導出 / 導入 ⭐

> 「**工程導出/導入**:完整打包工程為 ZIP(含圖片、視頻、文字、配置),換機或分享一包搞定」

完整 portable:換機、備份、分享都一個 ZIP 解決。

### 5.8 批量操作極為徹底

- **批量生成分鏡圖 / 批量生成分鏡視頻**:一鍵為所有缺圖/缺視頻分鏡批量生成
- **角色 / 場景影響分鏡面板**:資源卡片新增「↻ 重新生成分鏡圖」按鈕,**批量重新生成關聯分鏡**
- **多集劇本生成**:故事生成新增「生成集數」選項(1-6 集),AI 一次性輸出多集完整劇本

### 5.9 AI 配置三類獨立

> 「圖片生成、視頻生成、文本生成**三類模型獨立配置**」
> 「**內置『一鍵配置通義』『一鍵配置火山』快捷入口**,含 API Key 申請引導」

對使用者友善的 onboarding。

## 8. 不該抄的

- **Electron 桌面打包**:KuiperAI 是 SaaS,維持 Web app
- **SQLite 本地 DB**:KuiperAI 已經是 MySQL,不要切
- **Vue 3 + Element Plus**:KuiperAI 是 React + Tailwind,不要切
- **「數據不出本機」定位**:KuiperAI 是雲端產品,定位差異化

你是一位專業的短劇剪接導演。給定一系列已經產生過分鏡圖的 panels(編號、描述、地點、出場角色),請把它們**按照場景與角色連續性**切成多個 multi-shot 群組,每個群組 2-6 個 panel,讓每群可以送入 Kling 3.0 multi-shot=intelligence 一次合成一段 5-15 秒的連續視頻。

## 切組原則(從強到弱)

1. **同一場景同一角色**:同一個地點、相同主角的連續 panel 必須放在同群,確保 Kling 在生成時人物外觀一致。
2. **動作 / 情緒延續**:同一個動作序列(例如 走進房間→坐下→開口說話)放在同群,讓 Kling 知道這是一連串動作而非跳剪。
3. **節奏點**:當有「場景切換」、「時間跳躍」、「重要敘事轉折」時,**強制切群**(同群不跨場景)。
4. **群組大小**:盡量平均 4-5 個 panel/群,絕對不可有 1 個 panel 的孤群。若末尾只剩 1 個,合併到前一群(只要前一群 ≤ 5)。
5. **總群數**:大致是 panel 數 / 4 ~ panel 數 / 5,例如 30 panels → 6-8 群。

## 輸入

panel 數量:{panel_count}

panels(JSON,id 順序就是分鏡時序順序):
{panels_json}

## 輸出格式(嚴格 JSON,不要 markdown 不要任何其他文字)

```json
{
  "groups": [
    { "id": "g1", "panelIds": ["panel-uuid-1", "panel-uuid-2", "panel-uuid-3"], "reason": "客廳對話戲,女主角從走進到坐下" },
    { "id": "g2", "panelIds": ["panel-uuid-4", "panel-uuid-5"], "reason": "場景切到廚房,新動作序列" }
  ]
}
```

**硬性規則**:
- 每個 panel 只能出現在一個 group 裡
- 每群至少 2 個、至多 6 個 panel
- 所有 panel 都必須被分到某一群(沒有遺漏)
- panelIds 內順序必須是 panel 在原 storyboard 中的時序
- groups 之間的相對順序也要照原時序(g1 在 g2 之前表示 g1 第一個 panel 比 g2 第一個 panel 早)
- reason 用一句話(中文,< 30 字)寫為什麼這幾個 panel 該放一群

直接輸出 JSON,不要 ```json``` 包裹,不要前後文字。

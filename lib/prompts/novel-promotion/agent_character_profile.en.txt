Goals:
1. Identify characters that should appear visually OR have spoken lines (including OS / VO / narration / inner monologue).
2. Exclude pure background extras and abstract entities.
3. Build profile fields needed for downstream visual generation.
4. Capture naming/alias mapping, especially first-person references.

Extraction rules:
1. Include any character that either (a) appears on-screen OR (b) has dialogue/OS/VO/narration/inner monologue — even if they never visibly appear in the current episode.
   - Example: 桃桃 only appears via off-screen sobbing VO calling for her father. EXTRACT her — she is a named character with dialogue.
   - Example: 王玄's OS narration → extract 王玄 (he is on-screen anyway).
2. Exclude one-off nameless background people unless visual identity is required.
3. Resolve aliases/titles (e.g., "my husband", "boss", "I") to canonical names when possible.
4. For first-person narrative, explicitly document who "I" maps to in introduction.

Field rules:
- role_level: one of S/A/B/C/D based on narrative importance
- costume_tier: 1-5 based on social identity (not role_level)
- expected_appearances: always include at least one initial appearance (id=0); add id=1, 2... for persistent costume/age changes. ⭐ **Each expected_appearance entry MUST carry its own 80-150 word visual_description** (same rules as new_characters.visual_description, era-grounded): id=0 = the full look of the initial appearance; id=1,2... = the full look of that variant (same person — costume changes keep the face/hair and only change clothing; age changes such as de-aging or old-age memory must rewrite the age accordingly). This lets every look generate its own image instead of only the initial one. Only persistent visual changes warrant a sub-appearance — exclude effects/emotions/one-off actions.
  - Example: source says "adult cultivator in white robe → loses control and de-ages to ~18 → changes into modern casual wear" → emit 3 expected_appearances: id=0 "adult, white Daoist robe", id=1 "youth, de-aged, still white robe", id=2 "young man, modern casual wear", each with its own visual_description.
- introduction: include identity, relationship mapping, and common address mapping
- **appearance_mode: REQUIRED**, one of:
  - `on_screen` — appears in the visible frame this episode
  - `voice_only` — only heard via OS/VO/narration/inner monologue this episode, never visible
  - `mixed` — both on-screen and has OS/VO in this episode
  voice_only characters do not require a visual_description (downstream UI will let the user opt in to portrait generation).
- **voice_description: REQUIRED** for every extracted character (including voice_only ones). A one-sentence description of the character's dubbing voice/timbre, consumed by downstream TTS / dialogue video generation so the same character sounds consistent and on-character across every shot. Format: gender + 2-4 voice-quality adjectives (pitch, timbre, demeanor). Examples: "male, mature deep magnetic", "young female, bright and gentle", "middle-aged male, raspy and authoritative", "teenage boy, crisp and lively". Infer it from gender + age_range + personality_tags + role/archetype (e.g. a cold domineering CEO → "male, deep steady with authority"; a gentle virtuous heroine → "female, warm and soft"). Describe the VOICE ONLY — never appearance/visual info (that is visual_description's job).
